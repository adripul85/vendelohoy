## 2025-05-18 - Missing Authentication and Authorization in Vercel API Endpoints
**Vulnerability:** The `api-handlers/dispatch-courier.ts` API endpoint did not validate the Firebase Auth Bearer token and failed to check caller authorization. It only verified the presence of the `Bearer` token in the authorization header and assumed the caller was authorized to dispatch a courier for any transaction, allowing an unauthenticated or unauthorized actor to manipulate transaction states and dispatch couriers illegitimately.
**Learning:** Vercel API endpoints must authenticate requests by explicitly validating Bearer tokens using `adminAuth.verifyIdToken(token)` from `../lib/firebase-admin.js`. Simply checking for a token's presence is insufficient and insecure. Furthermore, verifying authentication is not enough; caller authorization must also be enforced by validating data ownership (e.g., verifying `decodedToken.uid` against the transaction's `sellerId`).
**Prevention:** Always parse and validate `Authorization` headers using `adminAuth.verifyIdToken(token)` in API endpoints. Always implement authorization checks correlating the decoded token's UID to the document being modified to ensure the caller has legitimate permissions.
