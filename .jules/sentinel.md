## 2026-08-17 - Fix authorization bypass in API
**Vulnerability:** The Vercel API endpoint for dispatching couriers (`api-handlers/dispatch-courier.ts`) completely lacked proper server-side token validation and authorization checks, aside from superficially verifying the presence of a Bearer token string. An attacker could send any random token starting with 'Bearer ' and successfully dispatch an item they do not own.
**Learning:** Vercel API endpoints must authenticate requests by explicitly validating Bearer tokens using `adminAuth.verifyIdToken(token)` from `../lib/firebase-admin.js`. Furthermore, caller authorization should be verified against data ownership (e.g., matching the decoded caller UID to the transaction's `sellerId`). Simply checking for the token's presence is insecure and creates an authorization bypass vulnerability.
**Prevention:** Always use Firebase Admin SDK to decode and verify JWTs on serverless API routes. Implement strict, explicit authorization logic after authentication to ensure users can only modify or access resources they own. Always cross-reference the decoded token's UID with the resource owner's ID.
