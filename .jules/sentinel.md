## 2024-05-18 - [Privilege Escalation via User Profile Updates]
**Vulnerability:** In `firestore.rules`, the `users/{userId}` update rule prevented updates to sensitive fields like `isAdmin` but missed the `role` field. Concurrently, Cloud Functions (`releaseFunds`, `refundFunds`) lacked real admin checks (hardcoded to false) and relied on the same `role` field for administrative access. A normal user could escalate privileges by setting `role: "admin"` in their profile.
**Learning:** Hardcoded placeholders (`const isAdmin = false`) in security-critical paths are dangerous. Relying on document fields for authorization requires ensuring those fields cannot be modified by the user themselves through database rules.
**Prevention:** Always ensure every field used for authorization (e.g., `role`, `isAdmin`) is strictly blocked from user modification in security rules (`firestore.rules`). Implement robust authorization checks dynamically by fetching user profile rather than hardcoding placeholders.
