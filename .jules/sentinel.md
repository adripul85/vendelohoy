## 2026-08-13 - [Authentication Bypass in API Endpoint]
**Vulnerability:** The Vercel API endpoint `api-handlers/dispatch-courier.ts` failed to adequately authenticate requests. It simply verified the presence of a "Bearer " string in the `Authorization` header and did not decode or validate the token against Firebase Auth. Furthermore, there was no check to ensure the caller had permission to modify the target transaction.
**Learning:** Checking for the presence of an authorization header without actually verifying the token cryptography and claims is an authorization bypass vulnerability. Any user could pass arbitrary tokens (or just the word "Bearer ") and gain unauthorized access to dispatch couriers for any transaction. Always validate tokens explicitly using `adminAuth.verifyIdToken(token)`. Furthermore, simple authentication is not authorization. The caller's identity (decoded UID) must be matched against the resource owner's identity to prevent Insecure Direct Object References (IDOR).
**Prevention:**
1. Vercel API endpoints must authenticate requests by explicitly validating Bearer tokens using `adminAuth.verifyIdToken(token)` from `../lib/firebase-admin.js`. Simply checking for the token's presence is insecure.
2. Caller authorization should be verified against data ownership (e.g., matching the decoded caller UID to the transaction's `sellerId`).
